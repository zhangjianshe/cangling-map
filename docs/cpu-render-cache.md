# CPU 绘制缓存

## 缓存层次

CPU 后端使用三层数据：

```text
源矢量数据
  → FlatGeobuf 预投影缓存
  → tiny-skia 几何、边界与文字绘制
  → .crgba 成员图层绘制缓存
  → 图层组 RGBA 合成
  → PNG/JPEG 编码
```

`.crgba` 位于 `MAP_CPU_RENDER_CACHE_PATH`，默认是 `${MAP_CACHE_ROOT}/cpu-render`。它保存成员
图层已经绘制完成的原始 RGBA，因此命中后不会再次访问 GDAL、计算几何、绘制边界或执行标签
碰撞和文字栅格化。图层组直接组合这些 RGBA，最终只执行一次 PNG/JPEG 编码。

文件包含 magic、格式版本、请求键、尺寸和 RGBA 长度，采用同目录临时文件、`fsync` 和原子
rename。读取时校验尺寸、总长度和 `MAP_CPU_RENDER_CACHE_MAX_ENTRY_MB`；损坏条目会被删除并
按当前请求自动重建。进程内另有按字节计费的 LRU，预算由 `MAP_CPU_RENDER_CACHE_MB` 控制。

## 失效条件

请求键包含：

- 数据主文件和 Shapefile 的 `.shp/.shx/.dbf/.prj/.cpg/.qix/.sbn/.sbx` 指纹；
- 图案样式图片的路径、大小和修改时间；
- 目标 CRS、BBOX、输出尺寸、缓冲、简化参数和背景；
- 当前缩放级别真正生效的样式规则。

任一输入变化都会生成新键，不会误用旧像素。旧文件属于可清理缓存，可随 `/cache` 生命周期
策略定期回收。

## 2026-10-21 实测

RTX 4060 主机（CPU 后端）、debug 构建、`china` 图层组、EPSG:3857、1969×1228、2× 像素比：

| 路径 | 耗时 | CPU 缓存指标 |
| --- | ---: | --- |
| 首次 CPU 绘制 | 3.49 s | 0 命中、2 未命中、2 写入 |
| 重启后的首个请求 | 1.01 s | 2 磁盘命中、0 未命中 |
| 同进程内存热请求 | 0.93 s | 新增 2 内存命中 |
| 人工截断一个缓存后 | 1.18 s | 1 磁盘命中、1 未命中、1 重建、1 错误 |

四次输出均为 364,203 字节，SHA-256 都是
`92cb19d7cfaffce511901cbc699a35a3d60bfe0c79da32e09cd44fed53ae6687`。重启后的首个请求相对
首次绘制降低约 71.0%，损坏恢复没有改变输出。
